# 游戏服发布与恢复记录

本流程在实际发布、迁移或恢复演练时使用，复用现有发布记录。开发 Task DONE 仅表示相应开发交付完成；本流程不修改引擎门禁，不要求每次 T2 小改动恢复数据库。未填写的实际值保持 UNKNOWN，不使用示例阈值作为生产默认值。

## 发布前记录

| 项目 | 本次应记录的内容 |
|---|---|
| 发布对象 | Task/代码版本、已验证制品摘要、生效配置/协议摘要、数据结构版本、操作人 |
| 测试与观察 | 命令/目标用例/结果、运行实例证据、隔离数据范围、未验证场景 |
| 兼容窗口 | 新读旧、旧读新、旧版本回写、旧客户端、降级后继续写的结论及测试证据 |
| 数据变更 | dry-run 的玩家范围/条数/资源总量、排除原因、幂等标识；实际执行前核对输入漂移 |
| 灰度 | 固定区服/玩家范围、长连接排空或迁移方式、跨服/共享数据影响、各阶段观察时长和样本量 |
| 放量条件 | 登录/结算失败率、P99、保存积压等少量相关指标；基线、阈值、时间窗和停止条件 |
| 恢复 | 功能关闭/流量隔离/版本回退/前向修复的命令或维护手册位置、适用前提、执行人 |
| 数据保护 | 有实际内容的备份、恢复验证记录、允许恢复耗时/丢失窗口、正常新增数据的保全与对账 |

发布晋级使用同一已验证制品。重新构建或修改配置后重新关联验证；不能只凭源码提交相同沿用结论。按实际风险安排备份及恢复演练，哈希清单不是备份。

## 逐批执行和异常处理

1. 核对实际实例版本与配置、相关依赖和权限，确认灰度范围及恢复路径可用。
2. 发布到固定灰度范围，对照未变更组观察业务与性能指标；样本不足、异常未解释时停止放量。
3. 达到预先记录的放量条件才扩大；每批记录时间、实例与观察结果。
4. 异常时先停止扩大影响。能安全降级才回退程序与配置；旧程序无法读写新状态时选择关闭相关能力、隔离或兼容修复。
5. 已发奖、扣费和交易按账目核对，补偿具有稳定业务标识并可安全重试。不得用恢复整库覆盖正常新增数据，也不把回退 JAR 当作撤销业务副作用。
6. 验证恢复后读写和关键业务，归档实际结论、失败证据、影响范围、补偿/清理结果及剩余问题。

跨版本数据格式优先先部署兼容读取，再启用新写入，兼容窗口结束后再清理旧表示；每步以项目实际存储契约验证。不能宣称单玩家队列提供跨玩家/跨节点事务。

## 交付记录最小格式

```text
发布/任务标识：
制品 + 配置 + 协议 + 数据版本：
目标实例/区服及场景关联证据：
实际测试与未验证范围：
灰度阶段/指标/停止条件：
回退兼容证据及不可逆影响：
备份恢复/数据补偿依据：
实际发布结果与异常处理：
```

该模板是记录格式，不是新增机器状态或默认通过证据。`UNKNOWN`、未执行、环境阻塞与失败分别说明，完整上线结论须有实际运行证据。
