# 红点模式

- 红点是业务状态的布尔或位图结论，优先实时推导；只有已读/未读等需要记忆的语义才单独保存。
- 先定义亮起和消失条件，再实现总入口、模块聚合与单一原因判断；具体接口名称沿用本项目现有约定。
- 先检查玩家、功能开关、活动窗口、参与/展示资格，再读取数据和扫描列表；复用上层已加载对象。
- 模块外只调用稳定聚合入口，不把内部业务规则复制到全局 Helper。
- 明确哪些子红点参与总红点、哪些仅页内展示；位含义稳定，不复用旧位表示新含义。
- 正常高频路径不刷大量日志；异常按 coding-style 记录上下文与异常对象，再按既定契约降级，不能静默吞错。
- 测试“满足条件亮起 → 领取/阅读后消失 → 重登仍正确”，并覆盖活动关闭、功能未开、子开关关闭、协议值和外层聚合。
