# 资源与奖励模式

本项目使用 `PlayerHelper.isEnough / delResources / addResources`；禁止直接调用 RewardHelper 或手改 GoodsModule 绕过资源链路。签名与重载见当前源码，辅助说明见 [ai-coding.md](../ai-coding.md)。

- 分清配置奖励描述、业务计算结果、持久化表示和协议 RewardInfo；不要借用其他项目的三层类型名，也不要凭字段猜测奖励类型。
- 先统一校验资格、状态、成本、次数和归属，再执行变化。多项成本用既有批量重载，不能循环逐个扣除而留下半成功。
- 扣费、奖励、领取位、事件、记录、通知/回包要一致；异常窗口明确补偿或重试语义。
- `notify` 与响应奖励承担不同用途；按 Protobuf 契约返回 `addResources` 的结果，避免漏展示或重复通知。
- 重复领取、重试、离线补发和结算恢复必须幂等；不能只靠按钮置灰防重。
- 保存遵守 Module/独立表机制。测试资源前后差、领取状态、保存后重载、回包/通知与重复请求无新增副作用。
