# 事件模式

本项目玩家事件通过 `EventTypeEnum`、Module 的 `getEventTypes()` 与 `player.fireAndHandleEvent(...)` 接入，细节见 [ai-coding.md](../ai-coding.md)。

- 事件定义说明参数顺序、类型、单位、来源、触发时机；生产者和消费者同步修改。
- 仅在目标业务成功后发送对应成功事件，失败、重试与补偿路径避免重复推进进度。
- 不在协议查询时临时推导一个“发生过”的事件；事件事实与当前状态查询分离。
- 玩家事件处理保持在所属队列，外部回调不能直接改 Module；共享单例不得缓存当前玩家。
- 先用低成本过滤确定是否关心事件，再读取数据或扫描任务；已有对象向下传递。
- 检查重复事件、重入、跨天、重登和异常中断时的行为，明确监听者失败会怎样影响调用方。
