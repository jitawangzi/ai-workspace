# 任务模式

- 先确定任务体系、配置 ID、目标值、条件类型、分组/阶段、重置周期及触发事件。
- 在真实行为发生的位置更新进度，使用本项目事件与 Condition 体系；列表查询只表达当前状态。
- 明确区分进行中、已完成、已领取、是否显示、红点、下一阶段开启条件。已领取不等于删除，完成不等于自动进入下一段。
- 晚开启的任务是否补判由条件语义决定：实时/历史累计型可依据当前事实补判，接取后事件计数型不能凭空追补。
- 补判、领奖和阶段推进须幂等；重复请求不重复发奖，未完成或错误归属不能领奖。
- 同一调用链复用已加载任务与玩家对象，高频事件避免全表扫描。
- 测试覆盖阶段衔接、晚开启、重登、跨天、重复领奖及协议列表/红点一致性。
