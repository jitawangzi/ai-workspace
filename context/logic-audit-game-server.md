# 游戏服务器逻辑专项审计：已知缺陷模式库

## 使用范围

在已经要求专项审查时供 logic-auditor 使用，普通开发也可作为自查。本文不为 T1/T2 新增独立审核或审批门禁。以当前源码和功能规则为证据；与强制规范冲突应报告，不能用“设计已批准”豁免。标明实际检查/不适用项及原因，不能把清单打勾当已执行测试。

## 缺陷模式与检查点

保留可迁移的原标准代号；其他行使用描述性名称，不伪称所有名称均为底座机器识别码。

| 模式 / 标识 | 风险及典型表现 | 本项目检查点与验证 |
|---|---|---|
| 并发重入与竞态 | 判断后跨异步窗口再次执行关键副作用 | 玩家队列归属、跨玩家/节点锁、回调重入、重复请求；锁范围与释放正确 |
| 锁内外快照不一致 | 加锁前读取旧对象，锁内直接保存 | 受保护范围内重读必要状态；不持锁执行无关慢 IO |
| 缓存/持久化不一致 | 回包或缓存已变，保存失败/延迟；旧异步回写覆盖新状态 | 常规 Module 保存链、DbEntity 独立表、保存完成信号、重登/节点切换与失败恢复 |
| 持久实体装配缺失 | 新模块/实体缺少加载、保存、注册或删除链 | 检查本项目现有生命周期；不要绕过公共存储造一套自用结构 |
| 恶意输入与跨账号越权 | 信任客户端归属、奖励数量、进度、层数 | 可信连接 playerId、范围/归属/资格/重复领取校验、请求顺序扰动 |
| 测试入口污染 | 正式逻辑调用 GM 或 fixture 直接改状态 | 正式协议 Act；GM 仅准备/观察/清理，环境权限有边界 |
| 关键副作用非原子 | 扣费、发奖、领取位、事件成功一半 | 每个失败窗口的回滚/补偿、批量部分失败、稳定幂等键 |
| 奖励与回包不一致 | 回包列出未实际入账奖励或漏填响应 | 实际 RewardInfo、notify 分工、资源增减/日志/通知一致 |
| **LAZY_RESET_UNPERSISTED** | 查询中 reset 内存并回包，保存链未覆盖变更 | 查询副作用进入现有 Module/DbEntity 保存；等待完成后新对象冷读；写入口也独立重置 |
| **LIMIT_STATE_POISONING** | 在旧周期次数上累加，再覆盖当前周期标识 | 写入口先按同一时间口径重置，再校验/累加，最后更新状态；直接写和边界日回归 |
| **IN_MEMORY_TEST_MIRAGE** | 只断言响应或同一 Player，误当落库证明 | 保存完成 → 存储重载新对象 → 断言真实字段；协议刷新不是冷重载 |
| 补偿/迁移不幂等 | 重试、跨天或重登重复发放/迁移 | 已结算标记、版本/周期、重放和中断后的恢复测试 |
| 周期口径不一致 | 00:00 与 05:00 混用、结束与销毁混用 | DateUtil、NewDay/NewDay5、活动/排行周期及逐字段保留/重置/补偿 |
| 重登重建缺失 | 未恢复监听、缓存、展示或补推 | 新对象加载、模块/活动生命周期、登录后重复触发 |
| 灰度回写覆盖 | 旧进程保存丢弃新字段或回退状态 | 新读旧、旧写新、客户端能力与发布窗口；显式迁移/兼容策略 |
| 日志不可追溯 | 静默吞错、只有错误码无上下文 | warn/error 与异常对象，玩家/活动/配置/操作/前后状态；控制敏感字段 |
| 自然稳定假设 | 把“发版后自然恢复”当补偿方案 | 必须有可执行保护/恢复步骤与验证证据 |

外部项目专属数据库分发表、扁平化实体的规则不复制为本项目 API 要求；可迁移的“登记装配完整、不可绕过现有存储”已纳入上表。

## 典型错误与修正形态

下列代码是审查用伪代码，不代表仓库已有同名函数。

### LIMIT_STATE_POISONING

```text
错误：count = count + 1；day = today
正确：若 day != today，按规则 reset count；校验额度；执行费用/奖励闭环；递增 count 并设置 day
```

先赋新周期会把旧次数固化。修正要复用同一时间口径并在写入口独立执行，不能要求客户端先 GET。测试：旧日已满 → 新日直接购买 → 再次查询/写入 → 保存后重登。

### LAZY_RESET_UNPERSISTED / IN_MEMORY_TEST_MIRAGE

```text
错误：查询 reset → 返回新值 → 断言同一对象的新值
正确：查询触发规范重置 → 确认字段进入实际保存契约且保存完成 → 从存储加载新对象 → 断言周期和计数
```

常规 Module 不因此强制每次手动 save；独立表按其写入契约。不能为测试便利扁平化或绕过生产模型。

### 重复发放与部分成功

```text
错误：先发奖励 → 再判断已领；或多项费用逐个扣除，最后一项失败
正确：先资格/已领/整体成本校验 → 按既有业务一致性边界执行 → 保存结算依据 → 返回实际结果；失败可确定地恢复
```

“加锁”或“在同一方法里”本身不是事务证明。枚举扣除后、发奖后、保存前和回包失败的重试结果，验证不会双发或吞资源。

## 报告格式与级别

| 级别 | 说明 |
|---|---|
| BLOCKER | 可越权、必然数据错乱、重复关键副作用等严重缺陷 |
| MAJOR | 高风险状态/恢复/一致性错误 |
| MINOR | 已定位但影响受限的边界风险 |
| INFO | 有证据的观察或改进建议 |

每项给模式名/标准代号、文件与位置、触发前提、状态轨迹、实际后果、修正建议和验证方法。实际命中才报告；未执行的集成验证明确标出。是否进入后续阶段由所选 T1/T2/T3 的引擎规则决定，本文件不另建治理流程。
