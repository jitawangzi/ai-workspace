# 游戏状态逻辑缺陷模式库

这是从近期实践迁移的检查清单，已按本项目线程和保存模型调整。T1/T2 可用于当前任务自检，不因此新增独立审核；已要求 logic-auditor 的任务须加载本文。具体功能语义依需求与设计，强制工程规范冲突应显式报告，不能自动用旧批准覆盖。

| 模式 | 检查重点 |
|---|---|
| 并发重入与跨队列写入 | 所属玩家队列、外部回调回投、单例状态、跨玩家/节点边界；不随意给串行业务加锁 |
| 归属与恶意输入 | 服务端核实玩家、对象归属、资格、金额、数量、索引和边界；不信任客户端进度 |
| 公共前置链被绕过 | 新类型/分支仍经过原有资格、限购、资源和支付校验 |
| 关键副作用半成功 | 批量成本、发奖、领取位、事件和响应的顺序及失败恢复 |
| 查询懒重置未保存 | 常规 Module 是否进入保存链路，独立表是否正确显式写入；保存后冷重载 |
| 跨周期计数污染 | 写入口先校验并重置周期，不依赖先查询；不先刷新时间戳再检查旧计数 |
| 内存断言假象 | 回包/缓存正确不代表 DB 正确，明确保存完成时点，重载为新对象后断言 |
| 奖励与通知不一致 | 实际资源、领取记录、推送和业务响应保持一致，失败不发成功事件 |
| 重试/补偿不幂等 | 重复请求、超时重试、重登补发与结算恢复不会重复扣/发 |
| 生命周期遗漏 | 初始化、重登重建、周期结束、删号和独立存储清理闭环 |
| 旧数据与混跑覆盖 | 缺省字段、幂等迁移、旧代码保存丢新字段、兼容窗口清理条件 |
| 接收方展示不兼容 | 依接收方能力过滤协议，保持拥有者真实值；检查未知配置 ID |
| 条件与展示混淆 | 完成/领取/阶段/显示/红点分离，晚开启补判符合条件类型 |
| 测试绕过正式入口 | GM 只准备/观察/清理，真实行为由正式入口触发；不得跳过断言冒充通过 |
| 高频重查与重计算 | 先轻检查，复用已加载对象，避免反复 IO 和无界增长列表 |
| 日志不可追溯 | 每个捕获分支至少 warn、异常对象和业务上下文；关键失败原因可区分 |

命中时记录具体位置、触发条件、影响、验证方法与级别；无证据不臆造缺陷。数据损坏/重复发奖等严重问题优先处理。未覆盖项与不适用项须说明。T3 的报告及门禁采用引擎规范，本文不另设批准步骤。
